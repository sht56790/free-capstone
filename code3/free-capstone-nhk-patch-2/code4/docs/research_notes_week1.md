# 1주차 - 조금 더 찾아봐야 하는 것들

## 1. 정규식 정확도 개선

### 계좌번호 패턴
- **현재**: `\d{4}[-\\s]?\d{4}[-\\s]?\d{4,6}|\d{12,14}`
- **확인 필요**:
  - 은행별 계좌번호 형식 (KB, 신한, 하나, 우리, NH농협 등)
  - 체크디지트 검증 로직 필요 여부
  - 가짜 양성 케이스 (일반 숫자열과 구분)

### 고객번호 패턴
- **현재**: `고객번호[:\\s]?\d{6,12}|\d{6,12}(?=\\s*고객)`
- **확인 필요**:
  - 실제 고객번호 형식 (자릿수, 하이픈 포함 여부)
  - 금융기관별 고객번호 규칙
  - 다른 컨텍스트에서의 숫자열과 구분

### 고객명 패턴
- **현재**: `[가-힣]{2,4}(?=\\s*(님|고객|분|씨))|[가-힣]{2,4}(?=\\s*계좌)|성명[:\\s]*[가-힣]{2,4}`
- **확인 필요**:
  - 희귀 성씨 처리 (예: 갈, 궉, 귀, 근 등)
  - 복합 성씨 (예: 남궁, 황보, 제갈 등)
  - 띄어쓰기 포함 이름 (예: "홍 길동")
  - 외국인 이름 처리 (영문, 한자 등)
  - 마스킹 방식 결정 ("홍○○" vs "홍*동" vs "[고객명]")

### 생년월일 패턴
- **현재**: `\d{4}[-.\\s]?\d{2}[-.\\s]?\d{2}|\d{6}(?=\\s*생년)|생년월일[:\\s]*\d{4}[-.\\s]?\d{2}[-.\\s]?\d{2}`
- **확인 필요**:
  - 유효한 날짜 검증 (1900~현재, 2월 29일 등)
  - YYMMDD 형식 처리 (6자리)
  - 가짜 양성 케이스 (예: "2024-12-31" 같은 미래 날짜)

### 전화번호 패턴
- **현국**: `010[-\\s]?\d{4}[-\\s]?\d{4}|0\d{1,2}[-\\s]?\d{3,4}[-\\s]?\d{4}`
- **확인 필요**:
  - 지역번호 형식 (02, 031, 032 등)
  - 080, 050, 070 등 특수 번호
  - 국제번호 처리 (+82 등)

### 주소 패턴
- **현재**: `([서울|부산|대구|인천|광주|대전|울산|세종|경기|강원|충북|충남|전북|전남|경북|경남|제주]\s*[시도군구]|\d{5}[-\\s]?\d{6})`
- **확인 필요**:
  - 우편번호 형식 정확성 (5자리-6자리)
  - 상세주소 패턴 (동, 호수 등)
  - 가짜 양성 케이스 (예: "서울시 강남구" 같은 일반적인 표현)

## 2. 금리·수수료 확정 표현 기준

### 확정 표현으로 판단할 키워드
- **현재**: "금리는 \d+%입니다", "수수료는 \d+원입니다"
- **확인 필요**:
  - "금리는 3.5%입니다" → 차단
  - "금리는 약 3~5% 범위입니다" → 허용
  - "금리는 상품에 따라 다릅니다" → 허용
  - "공개 수수료표 기준 5,000원" → 허용? 차단?
  - "예상 금리는 3.5%입니다" → 차단? 허용?
  - "과거 평균 금리는 3.5%였습니다" → 허용?

### 허용되는 완화 표현 목록
- **확인 필요**:
  - "약 ~원 범위"
  - "~원 대"
  - "상품에 따라 다름"
  - "영업점 문의"
  - "공개 자료 기준"
  - "참고용"

### 법무/컴플라이언스 컨설트 필요
- 금융상품 판매 관련 규정 확인
- 광고·표시 기준 준수 여부
- 과장 표현 기준 명확화

## 3. RAG 자료 범위 및 버전 정책

### 포함할 콘텐츠
- **확인 필요**:
  - 어떤 보험 상품? (생명보험, 손해보험, 건강보험 등)
  - 약관 범위 (일반약관, 특별약관, 개별약관)
  - FAQ 범위 (고객센터 FAQ, 상품별 FAQ)
  - 수수료/보험료 정보 (공개 자료 기준)
  - 가입 조건, 보장 범위
  - 공시 자료 (금리, 수수료 공시)

### 문서 형식
- **확인 필요**:
  - PDF 파일 (상품 설명서, 약관)
  - CSV/Excel 파일 (FAQ, 수수료표)
  - 웹 크롤링 (공개 자료)
  - 데이터베이스 연동

### 버전 관리
- **확인 필요**:
  - 문서 버전 필드 (시행일, 개정일)
  - 월 1회 갱신 주기 확인
  - 기존 인덱스 교체 방식
  - 버전 히스토리 관리

### 검증/업데이트 프로세스
- **확인 필요**:
  - 누가 자료를 제공/검증하는가?
  - 업데이트 승인 프로세스
  - 변경 알림 시스템

## 4. 모델 및 성능 검증

### Ollama 모델 선택
- **현재**: `qwen3:8b` (judge, regex 생성)
- **확인 필요**:
  - 속도 테스트 (3초 이내 응답 가능한가?)
  - 정확도 테스트 (금융 도메인 이해도)
  - 환각(hallucination) 비율
  - 대안 모델 비교 (llama3:8b, gemma:7b 등)

### Gemini 모델
- **현재**: `gemini-2.5-pro` (메인 응답 생성)
- **확인 필요**:
  - 금융 도메인 특화 프롬프트 효과
  - 응답 시간 (스트리밍 고려)
  - 토큰 사용량 및 비용

### 성능 목표
- **목표**: 응답 3초 이내
- **확인 필요**:
  - RAG 검색 시간
  - 모델 추론 시간
  - 전체 파이프라인 시간 측정
  - 병목 지점 파악

## 5. 출력 재검열 기준

### 확정적 금리·수수료 탐지
- **확인 필요**:
  - "금리는 3.5%입니다" 같은 확정 표현 자동 탐지
  - "수수료는 5,000원입니다" 같은 확정 표현 자동 탐지
  - "보험료는 50만원입니다" 같은 확정 표현 자동 탐지

### 거래 대행 유도 문장 탐지
- **확인 필요**:
  - "계좌 이체 가능합니다"
  - "대출 신청해드리겠습니다"
  - "바로 가입 가능합니다"
  - "지금 바로 처리해드립니다"

### 예외 처리
- **확인 필요**:
  - 공개 수수료표 인용 시 허용? (예: "공개 자료 기준 수수료는 5,000원입니다")
  - 과거 데이터 인용 시 허용? (예: "2023년 평균 금리는 3.5%였습니다")
  - 범위 표현 허용 (예: "약 3~5% 범위")

### 재처리 방식
- **확인 필요**:
  - 차단 (응답 전체 차단)
  - 수정 (경고 추가 후 수정)
  - 차단 + 핸드오프 (상담원 연결)

## 6. 상담원 핸드오프 기준

### 연결 조건
- **확인 필요**:
  - 계좌 이체 요청 시
  - 대출 신청 요청 시
  - 금리·수수료 계산 요청 시
  - 복잡한 질문 (정보 부족)

  - 재검열 차단 시

### 전달 요약 (비식별)
- **확인 필요**:
  - 질문 내용 (PII 제거)
  - RAG 답변 가능 여부
  - 맥락 정보 (고객 정보 제거)
  - 차단된 항목 목록

### 핸드오프 비율 목표
- **목표**: 20% 이하
- **확인 필요**:
  - 실제 비율 측정
  - 자동 처리 가능 범위 확대 방안
