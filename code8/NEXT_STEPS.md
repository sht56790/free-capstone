---

## 🎯 시연/발표 필수 항목 (우선순위 최상)

### Week 1 (지금부터 1주)

#### 1. **직원 보조 모드 개선** (필수) ⚡
현재 `staff_mode = True`로 하드코딩되어 있어 시연 시 문제가 될 수 있습니다.

**작업 내용**:
- 세션 기반 직원 모드 활성화 (사용자 role에 따라 자동 설정)
- 관리자 페이지에서 모드 ON/OFF 토글 기능 추가

**예상 작업 시간**: 2-3시간
**시연 영향**: 높음 - 시연 시 모드 전환을 보여줄 수 있음

---

#### 2. **벤치마크 테스트 실행 및 정확도 개선** (필수) ⚡
30개 테스트 케이스로 현재 성능을 측정하고 개선해야 합니다.

**작업 내용**:
- `config/benchmark_30_cases.json` 테스트 실행
- 정확도 측정 (Block/Mask/Allow 판정)
- 오판정 케이스 분석 및 패턴 개선
- 정확도 90% 이상 목표

**예상 작업 시간**: 6-8시간
**시연 영향**: 매우 높음 - 발표 시 정확도 수치를 보여줄 수 있음

---

#### 3. **시연용 데모 시나리오 준비** (필수) ⚡
부스 시연 시 보여줄 시나리오를 미리 준비합니다.

**작업 내용**:
- 대표적인 3-5개 시나리오 작성
  - 정상 케이스: 일반 질문 → 답변
  - 마스킹 케이스: 계좌번호 포함 → 마스킹 처리
  - 차단 케이스: 확정 표현 → 차단
- 시연용 스크립트 작성

**예상 작업 시간**: 2-3시간
**시연 영향**: 매우 높음 - 시연의 핵심

---

### Week 2 (2주차)

#### 4. **RAG 기능 구현** (가능하면) ⚡⚡
메뉴얼/FAQ 데이터를 읽어서 답변하는 기능이 있으면 시연 효과가 큽니다.

**작업 내용**:
- 벡터 DB 선택 및 설정 (ChromaDB 추천 - 간단함)
- 샘플 문서 인덱싱 (약관 일부, FAQ 일부)
- RAG 검색 및 컨텍스트 추가 기능
- 출처 표시 기능

**예상 작업 시간**: 3-5일
**시연 영향**: 매우 높음 - 차별화 포인트
**주의**: 문서 준비가 필요함 (없으면 생략 가능)

---

#### 5. **출력 재검열 기능** (중요) ⚡
LLM 응답에서 확정적 금리/수수료 표현을 자동 탐지합니다.

**작업 내용**:
- 응답 후처리 단계에서 재검열 로직 추가
- 확정 표현 패턴 탐지 및 차단/수정
- 간단한 예외 케이스 처리

**예상 작업 시간**: 2-3일
**시연 영향**: 높음 - 안전성 강조 가능

---

#### 6. **관리자 대시보드 개선** (중요) ⚡
시연 시 대시보드로 통계를 보여주면 좋습니다.

**작업 내용**:
- 실시간 통계 개선 (정확도, 처리 건수 등)
- 시각화 개선 (차트, 그래프)
- 벤치마크 결과 표시

**예상 작업 시간**: 2-3일
**시연 영향**: 높음 - 시각적 효과

---

### Week 3 (3주차 - 시연 직전)

#### 7. **안정성 개선** (필수) ⚡
시연 시 오류가 발생하지 않도록 안정성을 확보합니다.

**작업 내용**:
- 에러 처리 개선 (모든 예외 상황 처리)
- 에러 메시지 한국어화
- 타임아웃 처리
- 로그 개선

**예상 작업 시간**: 2-3일
**시연 영향**: 매우 높음 - 시연 실패 방지

---

#### 8. **시연 환경 준비** (필수) ⚡
실제 시연 환경을 구성합니다.

**작업 내용**:
- 시연용 데이터 준비
- 시연용 계정 준비
- 화면 캡처/녹화 준비
- 백업 계획 (오프라인 모드 등)

**예상 작업 시간**: 1-2일
**시연 영향**: 매우 높음

---

#### 9. **발표 자료 준비** (필수) ⚡
12/11 발표를 위한 자료를 준비합니다.

**작업 내용**:
- 시스템 아키텍처 다이어그램
- 성능 지표 정리 (정확도, 처리 시간 등)
- 데모 영상/스크린샷
- 개선 사항 정리

**예상 작업 시간**: 2-3일
**시연 영향**: 매우 높음

## ⚠️ 위험 요소 및 대응 방안

### 1. RAG 기능 시간 부족
- **대응**: 없어도 시연 가능 (기존 기능만으로도 충분히 시연 가능)
- **대안**: 간단한 FAQ 하드코딩으로 대체

### 2. 정확도가 목표치에 못 미침
- **대응**: 벤치마크 결과를 투명하게 공개 (개선 여지 설명)
- **대안**: 오판정 케이스를 분석하고 개선 계획 제시

### 3. 시연 중 오류 발생
- **대응**: 오프라인 모드 준비, 데모 영상 백업
- **대안**: 시연 전 충분한 테스트 수행
